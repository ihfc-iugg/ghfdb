# CONTEXT.md — domain glossary

The vocabulary this repository speaks. Use these terms, with these meanings, in issues, commit
messages, documentation, test names and code. Where a term has a tempting synonym, the synonym to
avoid is named.

Two rules govern this file:

1. **Definitions describe the package as it stands.** Where something is planned rather than built,
   it says so.
2. **Terms match the GHFDB portal's where the two overlap.** The portal's glossary
   ([ghfdb-portal `CONTEXT.md`](https://github.com/ihfc-iugg/ghfdb-portal/blob/main/CONTEXT.md))
   defines the heat flow data model. A word that means one thing there must not mean another here.

## Naming discipline

| Term | Meaning |
|---|---|
| **GHFDB** | The Global Heat Flow Database as a body of data. |
| **GHFDB release** | A published, citable version of the data, distributed with a DOI through GFZ Data Services. |
| **GHFDB portal** | The web application at portal.heatflow.world, with its own validation and scoring. Never "the database". |
| **GHFDB structure** | The definition of what a heat flow record contains: its fields, their types and their vocabularies. This repository describes it in the **field schema**. |

Never write "the database" unqualified.

## Spreadsheets

| Term | Meaning |
|---|---|
| **Upload template** | The official spreadsheet a contributor fills in: one sheet named `data list`, a header row of field codes, description rows, then one row per child. Generated by this repository from the field schema (planned). |
| **Workbook** | One filled-in upload template: the only kind of file this package reads. |
| **Description rows** | The rows under the header that describe each field: obligation, domain, quality relevance, name, published column name, unit and allowed range. Generated from the field schema, and ignored when a workbook is read. |

Other layouts exist, such as the GHFDB release format and the data assessment team's working spreadsheets. This package does not read them. The upload template is what is distributed to the research community, so it is the one format checked here.

## Fields

| Term | Meaning |
|---|---|
| **Field** | One column of the GHFDB structure. |
| **Field code** | A field's short identifier: `P1`–`P13` for parent fields, `C1`–`C49` for child fields. The header row of the upload template. |
| **Published column name** | A field's name in row 6 of the upload template and in GHFDB release files, such as `q`, `lat_NS` or `T_grad_mean`. Its casing is part of the name. |
| **Obligation** | Whether a field must be filled: `M` mandatory, `R` recommended, `O` optional. |
| **Field schema** | The machine-readable description of every field, as a Frictionless Table Schema: type, unit, obligation, range and allowed values (planned). |

## The heat flow data

The data-model terms are the portal's, and are not redefined here: **heat flow**, **site**,
**depth interval**, **parent**, **child**, **thermal gradient**, **interval conductivity**,
**correction**.

The upload template holds one row per **child**, with its parent's fields repeated on every row
belonging to it. A **relevant child** is one marked as used in deriving its parent's value (field
`C9`).

Avoid "determination", "entry" and "record" for a row. Say **child**.

## Checking

| Term | Meaning |
|---|---|
| **Check** | Comparing a workbook with the field schema and the cross-field rules. It reports and never changes the workbook. |
| **Problem** | One thing a check found wrong with one cell or row, with its Excel row number, field and kind. Not "error", "violation" or "flag". |
| **Problem kinds** | **Missing** (a mandatory field is empty), **wrong type** (text in a number field, a fraction in a whole-number field), **out of range**, **not in vocabulary**, and **rule** (a cross-field rule is broken). |
| **Cross-field rule** | A rule that relates two or more fields, for example "when the exploration method is indirect, the temperature method must be an estimate". The field schema cannot express these. |
| **Suggestion** | A vocabulary term offered with a not-in-vocabulary problem when the value is close to one, as in "did you mean `[Core samples]`?". |

## Vocabularies

| Term | Meaning |
|---|---|
| **Controlled vocabulary** | One of the IHFC Controlled Vocabularies: a SKOS concept scheme with a persistent URI, published as a versioned release. Reserve "vocabulary" for these. A list of column names is not a vocabulary. |
| **Concept** | One entry of a controlled vocabulary, identified by its URI. |
| **Term** | How a concept is written in a workbook cell: its label or notation in square brackets, such as `[Core samples]` or `[LOGeq]`. |
| **Vocabulary release** | The version of the IHFC Controlled Vocabularies the field schema is generated from, such as `v2026.1`. |

## Quality

| Term | Meaning |
|---|---|
| **Quality scheme** | The rules that score a child: the U-score, the M-score and the perturbation flags, after Fuchs et al. (2023), with every departure from the paper documented. |
| **Scheme version** | A released, fixed version of the quality scheme, such as `2027.1`, with its worked examples. Separate from the package version (planned). |
| **Worked example** | One child's input values with its expected scores. The worked examples are part of the scheme and are the tests every implementation runs. |
| **U-score** | The grade of a child's uncertainty, `U1`–`U4`, from the coefficient of variation. `Ux` when it cannot be determined. |
| **M-score** | The grade of a child's methodology, `M1`–`M4`, from the product of its T-score and TC-score. `Mx` when it cannot be determined. |
| **T-score**, **TC-score** | The numbers the M-score is made from: how well the temperature gradient and the thermal conductivity were determined. Each starts at 1.0 and takes a penalty per criterion. |
| **Rules** (probe sensing, borehole and mine) | The two sets of criteria for the T-score and TC-score. A child is scored by one of them, chosen by its site's exploration method. |
| **Missing-information mark** | The `x` after an M-score. Set when an input the scheme needed was empty, in which case that criterion took its largest penalty. Not to be confused with `Mx`. |
| **Not determined** | No score could be made: `Ux`, `Mx`, or a T-score or TC-score left empty. Never written as 0. |
| **Perturbation flags** | Seven characters recording each disturbing effect's state, in the order `S E T P V C R`. Not "P-score". |
| **Quality code** | The U-score, M-score and perturbation flags written as one string, such as `U2.M3x.-e-PX--`. |
| **Inherited code** | The quality code a parent takes from its relevant children. |
| **Preview score** | Any score this package computes. The GHFDB portal recalculates every score itself, and its value is authoritative. |

## People

| Term | Meaning |
|---|---|
| **Data assessment team** | The people who prepare GHFDB data from publications and check it before submission. This package's users. |
| **Data assessor** | A member of that team. |
