# Upload template

The GHFDB upload template is the workbook a data assessor or contributor fills in with
heat-flow data. Download the template for this version of ghfdb, enter your data on its
`data list` sheet and follow the choice lists where a field offers them.

{upload-template-download}

## The three sheets

The workbook has three sheets:

- `readme` names the package version the template was generated by and where the
  vocabularies are published, and links the field reference.
- `data list` is the sheet you fill in. Row 1 holds the field codes. Rows 2 to 8 describe
  each field: its obligation, domain, quality relevance, name, published column name, unit and
  allowed range of values. Enter one record per row from row 9.
- `controlled vocabulary` lists the allowed terms of each field that has a fixed list.

Every field is described in full in the [field reference](fields/index.md).

## Fill in the template

1. Download the workbook above and open it in a spreadsheet program.
2. Go to the `data list` sheet and read rows 2 to 8 of the column you are filling in.
3. Enter your values from row 9. Where a cell offers a choice list, pick a term from it.
4. Save the workbook under a name of your own.

## Changes from the hand-maintained template

This template follows version 2026.03 of the GHFDB submission template
([Fuchs et al., 2025](https://doi.org/10.5880/fidgeo.2025.042), CC BY 4.0), which is maintained
by hand and distributed by the GHFDB portal. The lists below are computed from the two workbooks each time the
documentation is built, so they show every difference in the fields, the description rows and
the allowed terms.

Both workbooks put each field's terms on the `controlled vocabulary` sheet under the same column
letter as the field on `data list`. In this template the two rows above the terms hold the field
code and the field's name.

{upload-template-changes}

## Why the template is generated

The template is generated from the same field schema the field reference is built from, so the
two cannot disagree. The field schema and the published vocabularies go into the package's upload
template generator, and the documentation build writes the result beside this page.

```{mermaid}
flowchart LR
    schema["Field schema"] --> template["Upload template generator"]
    vocabularies["Published vocabularies"] --> template
    template --> build["Documentation build"]
    build --> download["Download on this page"]
```

## Why choice lists accept any value

Fields with a fixed list of allowed values get a choice list. The list offers the allowed
terms and accepts any value, so a term that is not offered can still be entered. The readme
sheet names the package version, so a workbook can always be traced
to the template it came from.
