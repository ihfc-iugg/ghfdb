# Feature Specification: Check a workbook and get a report of every problem

**Feature Branch**: `003-check-a-workbook`

**Created**: 2026-11-05

**Status**: Draft

**Serves**: G1, G2 · **Roadmap**: R3 · **Depends on**: FS-001, the field reference ([#4](https://github.com/ihfc-iugg/ghfdb/issues/4)), and FS-002, the generated upload template ([#5](https://github.com/ihfc-iugg/ghfdb/issues/5)), both delivered

**Input**: [#21](https://github.com/ihfc-iugg/ghfdb/issues/21), "Check a workbook and get a report
of every problem": data assessors need to find every mistake in an upload template workbook before
it is submitted, without reading it field by field against the field reference. One command checks
a workbook and writes a report copy beside it, leaving the original untouched, with every problem
listed against its child: a mandatory field left empty, text where a number belongs, a fraction in
a whole-number field, a value out of range, or a term that is not in the vocabulary, with a
suggestion when the value is close to one. Each problem names its Excel row, its field and its
kind. Workbooks with a different number of description rows, or with empty pre-numbered rows at the
end, are still read correctly.

## Overview

A data assessor runs one command on a workbook. The check compares every child in it with the
field schema (FS-001) and the vocabularies the field schema links to, and writes a report copy
beside the workbook. The report copy holds the workbook's data with every problem shown against
the child it belongs to, and a list of every problem with its Excel row, field and kind. The
original workbook is never changed.

This is the package's first command, and the first part of the package the data assessment team
can use. It reads upload templates generated by this package (FS-002) and the hand-maintained
upload templates that came before them.

**Out of scope**

- Cross-field rules, including a field that is mandatory in one domain only, because which domain
  a child belongs to is read from its other fields (R4).
- Quality scores (R6) and inherited codes (R10).
- Fixing a problem in a new copy of the workbook (R12).
- Checking a dataset the size of the GHFDB in seconds (R11). The check works on whole columns from
  the start (Constitution, Article XIII), but no speed target is set here.
- Other spreadsheet layouts, such as the GHFDB release format.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - A data assessor checks a workbook and reads every problem in it (Priority: P1)

A data assessor has a workbook filled in from a publication. They run the check on it from the
command line. The check writes a report copy beside the workbook and tells them how many children
it read and how many problems it found. They open the report copy and go through the problems one
by one: each names the Excel row of the child, the field, the kind of problem and the value found,
and a value that is close to a vocabulary term comes with a suggestion. The workbook they checked
is exactly as it was.

**Why this priority**: This is the feature. Without it the data assessment team checks workbooks
by eye against the field reference, or with a tool whose reports are wrong.

**Independent Test**: Run the command on a workbook with known problems in it, one of each kind,
and compare the report copy with the list of problems put there. Compare the original workbook
with a copy taken before the run.

**Acceptance Scenarios**:

1. **Given** a workbook, **When** an assessor runs the check on it, **Then** a report copy is
   written beside it under a name that tells it apart from the original, and the original file is
   byte for byte as it was.
2. **Given** a mandatory field left empty on a child, **When** the workbook is checked, **Then**
   the report lists a missing problem for that child's Excel row and that field.
3. **Given** a recommended or optional field left empty, **When** the workbook is checked, **Then**
   no problem is reported for it.
4. **Given** text that is not a number in a number field, such as `about 60` or `1,234.5`, **When**
   the workbook is checked, **Then** the report lists a wrong-type problem with the value as found,
   and never a missing problem, whatever the field's obligation.
5. **Given** a fraction such as `3.5` in a whole-number field, **When** the workbook is checked,
   **Then** the report lists a wrong-type problem with the value as found.
6. **Given** a value in a field with a set format, such as a year and month, that does not have
   that format, **When** the workbook is checked, **Then** the report lists a wrong-type problem.
7. **Given** a number below a field's minimum or above its maximum, or text longer than a field's
   maximum length, **When** the workbook is checked, **Then** the report lists an out-of-range
   problem with the value as found.
8. **Given** a value in a vocabulary field that is not a term of that field's vocabulary as
   currently published, **When** the workbook is checked, **Then** the report lists a
   not-in-vocabulary problem with the value as found.
9. **Given** a not-in-vocabulary value that is close to a term, such as `Core samples` without
   its brackets, a different capitalisation, or a small misspelling, **When** the workbook is
   checked, **Then** the problem carries that term as a suggestion. A value close to no term
   carries no suggestion.
10. **Given** a field that may hold several values separated by its separator, **When** the
    workbook is checked, **Then** each value is checked on its own and each problem names the
    value it is about.
11. **Given** a child with several problems, **When** the assessor reads the report copy, **Then**
    every one of them is reported, each with the child's Excel row and its own field and kind.
12. **Given** any problem, **When** the assessor reads it, **Then** its row number is the row
    number Excel shows for that child.
13. **Given** a workbook whose description rows are more or fewer than the generated template's,
    **When** it is checked, **Then** the data is found where it starts and the description rows
    are neither checked nor reported.
14. **Given** a workbook with rows at the end that hold an `ID` and nothing else, **When** it is
    checked, **Then** those rows are not children and nothing is reported for them.
15. **Given** a workbook from an earlier upload template, with a column under a published column
    name the field schema records as an earlier name of a field, **When** it is checked, **Then**
    the column is checked as that field.
16. **Given** a column the field schema does not know, a field the workbook has no column for, or
    two columns for the same field, **When** the workbook is checked, **Then** the report lists the
    column problem once for the workbook, not on every child. A missing column for a mandatory
    field is also reported as missing on every child.
17. **Given** a workbook with no problems, **When** it is checked, **Then** the report copy is
    still written and says that no problem was found.
18. **Given** a run of the check, **When** it finishes, **Then** the command states how many
    children it read and how many problems it found in how many of them, and ends with a status
    that tells a script whether problems were found, none were found, or the check could not run.
19. **Given** a report copy, **When** anyone reads it later, **Then** it states the package version
    and the vocabulary release it was checked against, and when the check ran.
20. **Given** a workbook checked before, **When** it is checked again, **Then** the earlier report
    copy is replaced and the original is still untouched.
21. **Given** the vocabularies were downloaded by an earlier run, **When** the check runs with no
    network connection, **Then** it checks the workbook against the vocabularies it has kept.
22. **Given** the package's documentation, **When** an assessor looks up the command, **Then** a
    reference page describes how to run it, what it writes and how to read every part of the
    report copy, with each problem kind explained.

---

### Edge Cases

- A cell holding a formula: the value Excel last saved for it is checked, and the formula is never
  calculated. A formula cell with no saved value is checked as empty.
- A number stored in a cell as text, where the text reads exactly as a number, such as `12.5`: it
  is checked as that number, because the value is the one the assessor typed and nothing is
  changed or dropped. Text that reads as a number only after something is removed or replaced
  (`1,234.5`, `12,5`, `60 mW`) is a wrong-type problem.
- A cell Excel holds as a date in a field whose format is a year and month: a wrong-type problem,
  because the cell holds a full date rather than a year and month.
- A cell with spaces only: checked as empty.
- A file that is not an upload template workbook (no `data list` sheet, or no header row of field
  codes): the check stops with a message saying what it could not find, writes no report copy and
  ends with the could-not-run status.
- A file that cannot be opened, or a folder where the report copy cannot be written: the check
  stops with a message naming the file or folder and ends with the could-not-run status.
- The vocabularies have never been downloaded and there is no network connection: the check stops
  with a message saying it needs to download them once, and ends with the could-not-run status.
- The report copy is open in Excel and cannot be replaced: the check stops with a message saying
  so, and the earlier report copy is left as it is.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: The package MUST provide a command that checks one workbook given by its path.
  (US1)
- **FR-002**: The check MUST NOT write to, move or rename the workbook it was given. It MUST write
  its report to a separate report copy beside the workbook, replacing an earlier report copy for
  the same workbook. (US1)
- **FR-003**: Every rule the check applies MUST come from the field schema and the vocabularies it
  links to: obligation, type, format, range, maximum length, separator and allowed terms. No rule
  and no term is written into the check by hand. (US1)
- **FR-004**: The check MUST report each problem as exactly one of the problem kinds: missing,
  wrong type, out of range or not in vocabulary, or as a column problem for the workbook. An
  invalid value MUST NOT be reported as missing, and no value may be changed, coerced or dropped
  without a problem being reported. (US1)
- **FR-005**: A missing problem MUST be reported for every child on which a field that is mandatory
  in every domain is empty. Fields mandatory in one domain only are not checked for missing values.
  (US1)
- **FR-006**: Every problem on a child MUST name the child's Excel row number, the field code and
  published column name of its field, its kind and the value as found. (US1)
- **FR-007**: A not-in-vocabulary problem MUST carry a suggestion when the value is close to one
  term of the field's vocabulary, and none otherwise. (US1)
- **FR-008**: The check MUST find the header row by its field codes, read data from the first row
  after the description rows, whatever their number, and treat a row holding nothing but an `ID`
  as no child. (US1)
- **FR-009**: The check MUST recognise a column under its field code, its published column name or
  any earlier column name the field schema records for it. (US1)
- **FR-010**: The report copy MUST show every problem against the child it belongs to, and list
  every problem of the workbook in one place. (US1)
- **FR-011**: The report copy MUST state the package version, the vocabulary release and the time
  of the check. (US1)
- **FR-012**: The command MUST state how many children it read and how many problems it found in
  how many children, and MUST end with one status for no problems, another for problems found and
  a third for a check that could not run. (US1)
- **FR-013**: A cell's formula MUST never be calculated, and nothing read from a workbook may be
  executed or used to build a path or a command. (US1)
- **FR-014**: The check MUST run without a network connection once the vocabularies it needs have
  been downloaded. (US1)
- **FR-015**: The documentation MUST have a reference page for the command and the report copy,
  explaining every problem kind, and the change MUST be recorded in `CHANGELOG.md`. (US1)

### Key Entities

- **Workbook**: the filled-in upload template the assessor checks. Read, never written.
- **Report copy**: the file the check writes beside the workbook, holding its data, its problems
  and what it was checked against.
- **Problem**: one thing wrong with one cell of one child, with its Excel row, field, kind and the
  value found, and a suggestion where there is one.
- **Column problem**: one thing wrong with the workbook's columns as a whole: a column the field
  schema does not know, a field with no column, or two columns for one field.
- **Field schema** (FS-001): where every rule the check applies comes from.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: On a workbook seeded with one problem of every kind in known cells, the report lists
  every seeded problem with its correct Excel row, field and kind, and no other problem.
- **SC-002**: Every problem the old checking tool misreported is reported correctly: text in a
  number field as wrong type rather than missing, a fraction in a whole-number field as wrong type
  rather than truncated, and every row number as the row Excel shows.
- **SC-003**: After any run, successful or not, the checked workbook is byte for byte identical to
  the file before the run.
- **SC-004**: A workbook generated by this package and filled in correctly, and the same data in
  the last hand-maintained upload template, are each reported with no problem.
- **SC-005**: An assessor who has never used the command can run it and find a given problem in
  the report copy by following the reference page alone.

## Clarifications

### Session 2026-11-05

- Q: Which empty fields are missing problems, given that some fields are mandatory in one domain
  only? → A: Only fields mandatory in every domain. A child's domain is read from its other fields,
  which makes domain-only obligation a cross-field rule, and cross-field rules are R4. Integrated
  as FR-005 and the out-of-scope list.
- Q: Is an empty recommended field a problem? → A: No. "Missing" is defined as a mandatory field
  left empty (`CONTEXT.md`). Integrated as Acceptance Scenario 1.3.
- Q: Which problem kind is a value that breaks a field's set format, such as a year and month?
  → A: Wrong type. The format is part of what the field's type allows. Integrated as Acceptance
  Scenario 1.6.
- Q: Which problem kind is text longer than a field's maximum length? → A: Out of range, the kind
  for a value beyond a limit the field schema sets. Integrated as Acceptance Scenario 1.7.
- Q: How are columns that do not match the field schema reported? → A: Once, as a column problem
  for the workbook, so one wrong column does not bury the report under a problem on every child. A
  mandatory field with no column is also missing on every child, because that is what the children
  hold. Integrated as Acceptance Scenario 1.16 and FR-004.
- Q: What does the command tell a script about the result? → A: Three statuses: no problems,
  problems found, could not run. Integrated as Acceptance Scenario 1.18 and FR-012.

## Assumptions

- The report copy is written in the same spreadsheet format as the workbook, so the assessor reads
  it in the program they filled the workbook in. Its layout is settled at planning, within FR-010
  and FR-011.
- The vocabularies are downloaded and kept the way the field schema already does it (FS-001), so
  the check adds no download of its own.
- "Close to a term" is settled at planning. It covers at least a term without its square brackets,
  a different capitalisation and a small misspelling, and never offers more than one suggestion.
- The glossary gains an entry for **report copy** and **column problem** with the build, so the
  words in the report, the documentation and the code are defined.
